# 逐句阅读器

一句一屏地读 Markdown / EPUB / TXT。当前句大字居中，前后句淡色提示，按空格翻页——像看字幕一样读书。

**在线使用：** https://wangbrightly.github.io/sentence-reader/

## 用法

打开页面，把 `.md`、`.epub` 或 `.txt` 文件拖进窗口（或点「打开文件」）。

| 操作 | 按键 |
|---|---|
| 下一句 / 上一句 | `空格` `→` / `←`，或点屏幕右半边 / 左半边 |
| 下一章 / 上一章 | `]` / `[`，或用顶部章节下拉框 |
| 开头 / 结尾 | `Home` / `End` |
| 自动播放 | `P`（停留时间按字数计算，速度可调） |

会记住上次读的书和读到哪一句，下次打开直接续读。

## 隐私

整个阅读器只有一个 HTML 文件，没有服务器，也不联网。书的内容只在你自己的浏览器里解析和保存，不会上传到任何地方。也可以下载 `index.html` 到本地双击使用。

## 局限

- EPUB 插图会显示；Markdown 里的图片只显示图片说明；公式和注释链接会丢失
- 按标点断句，`Dr.` 这类英文缩写偶尔会被误切
- 不支持带 DRM 加密的 EPUB

## 开发统计（截至 2026-10-09，v0.1.2）

- **代码量**：1487 行（网页版 `index.html` 577 行，其中样式 154 行、脚本 314 行；Kotlin 主代码 249 行、Kotlin 单元测试 155 行、网页端 Puppeteer 测试 304 行、XML 97 行、Gradle 脚本 92 行、打包脚本 13 行），另有 52 行 DEV_WORKFLOW.md 开发进度与踩坑记录。
- **提交次数**：15 次。首版网页没有自动化测试；从安卓版起，每个改动都先写测试、确认失败、再写实现（红绿在同一次提交里，提交记录里看不出配对），每次发版前真机验收。累计新增 1737 行、删除 27 行——删除量很少，因为返工大多发生在提交之前（比如中文粗体在真机上加不粗、改用描边模拟）。
- **开发时长**：约 6.3 小时，跨 2026-10-08 至 2026-10-09 两天（按开发对话的消息时间戳估算：相邻消息间隔 ≤90 分钟计入连续工作时间，超过按休息处理，此为估算方法，非精确计时；若按提交时间戳估算只有 2.9 小时，因为提交稀疏、一次提交前常连续工作数小时，会严重低估）。
- **对比人工独立开发**：本项目是一个零依赖的单文件阅读器网页（Markdown / EPUB 解析、按中英文标点切句、自动播放、手机界面与深浅色）加安卓 WebView 外壳（文件选择与「用…打开」、返回键、屏幕常亮、正式签名发布），以界面与平台对接为主，估算约 200～300 行/日"测试通过、真机验证过"的代码。按净新增约 1500 行估算，传统手写方式约需 **5～8 个工作日**；AI 辅助后实际耗时约为其 1/6～1/10（未计入界面设计稿的制作时间）。此项为估算，非精确测量。

## 安卓版

`android/` 目录是安卓 App：WebView 直接显示本仓库的 `index.html`（每次编译自动复制进去），支持 App 内打开文件和文件管理器「用…打开」md/epub/txt，阅读进度跨重启保留。

**下载安装：** 到 [Releases](https://github.com/wangbrightly/sentence-reader/releases) 下载最新的 `sentence-reader-v*.apk`，在手机上打开安装（需允许「安装未知来源应用」）。

自己编译：

```sh
cd android
JAVA_HOME=/usr/local/opt/openjdk@21 gradle testDebugUnitTest assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

网页端手机界面测试：`node --test tests/*.test.mjs`（需要本机装有 Puppeteer）。
